# Changelog

## Unreleased

- Waking the Mac no longer drops working remote connections. The websocket keep-alive dropped a socket once 60 s passed without a pong, and its timer stops while the Mac sleeps, so the first tick after a wake counted the whole sleep as silence and dropped the ChatGPT (`durable`) app-server connection even when it still worked; every open thread then resynced and its stream restarted. A tick that comes more than two intervals late now pings first and allows 5 s for the answer, so a dead socket is still dropped within about 10 s of a wake (it took 60 s before) and a live one is kept. In the logs of one Mac, 13 of 29 pong timeouts came within two minutes of a wake: 3 dropped the socket within 2 s of waking and 10 took 59–69 s to notice a dead one.
- Streaming replies render less per frame. Every word of a streaming reply was its own fading `<span>`, and every frame rebuilt and reconciled a span for every word of the message, so frames cost more the longer the reply got. Words whose fade has finished are now plain text; only the words still fading are elements.
- While a reply streams, blocks above the one being written are reused instead of rebuilt and compared again every frame. In a 30 KB test reply (real chunks with React's own reconciler, without Chromium's layout and paint) render time per frame near the end of the reply fell from 7.5 to 3.1 ms, and the page is the same after every frame.
- Measured live with the same prompt on GPT-6.1 Sol Medium (three runs each, 18–19 KB replies): the renderer used a median of 3.03 CPU-seconds per 1,000 characters streamed on stock ChatGPT and 2.19 on Codex++ (−28%; ranges 2.33–3.07 and 1.90–2.61), and a median of 91% of a core against 56% over the last quarter of the reply.
- The startup adapter walks each module's syntax tree once instead of once per edit: 46 s fell to 12 s on build 20398, with byte-identical output. Past the 60 s discovery limit the patch had installed without any startup edits.
- When startup discovery times out or crashes it is retried once with a 180 s deadline; if it still fails, the patch or upgrade stops and the installed app is unchanged, instead of installing without startup speed-ups. The helper menu warns "Startup Speed-ups: Not Applied" when the installed patch has no discovery report, and the report records how long discovery took.
- `scripts/review-build.py` reviews a new ChatGPT build in one command through the same discovery code patching uses: every edit of every adapter applied or skipped with a diagnosis, timings, and a diff against the last reviewed build that fails when a release edit stops applying (docs/reviewing-a-new-build.md).
- At startup ChatGPT listed every MCP server twice in a row: each window start replays the app-server's initialization message, and the replay made the app fetch the full MCP list again right after the first fetch. A replay that repeats what the window already has no longer triggers the second fetch.
- Images attached to a ChatGPT conversation are sized, and above 2048 px or 1 MB scaled and re-encoded, in a worker instead of on the window's main thread (40–215 ms of main-thread work per 5K image fell to 2–10 ms in headless Chrome). Sizes, types and thresholds are unchanged; PNG output is byte-identical and JPEG output differs very slightly (46–51 dB PSNR).
- Heavy terminal output, measured live (`seq 1 400000`, two runs each): the renderer peaked at 204–240% of a core and used about 1.3–2.1 CPU-seconds on stock ChatGPT, against 70–76% and 0.3–0.7 CPU-seconds with Codex++.
- Output from a running command updates the thread as a change to that command only, as streamed reply text already does, instead of as a change to the whole conversation 20 times a second (about 0.39 to 0.04 ms per flush in a measured long thread).
- The "Restart to update" pulse fades a pre-painted layer with opacity, which the compositor animates, instead of restyling and repainting the button every frame for as long as an update waits; it pauses while the window is in the background. The OpenAI-logo loading sweep slides a gradient painted once instead of animating its background position.
- The pet window's "thinking" shimmers move again: that window can never take focus, so Codex++'s shimmer replacement treated it as permanently in the background. It now leaves that window's shimmers as stock.
- When macOS denies access to Chrome's profile folder, the Chrome extension check retries after 1 minute, doubling up to 1 hour, and at once when the app becomes active again, instead of on every launch step and window focus; the warning is logged once per episode (900 lines in three days in one Mac's logs).
- Token usage, goal and environment updates for a thread are applied only in windows that have it loaded, which stops "Conversation state not found" errors in hidden windows. IPC clients no longer log a warning for the router's client-status and connection-reset notices they receive by design (2,639 lines in three days), and the harmless ResizeObserver loop notice is no longer reported as a global error (296).
- Empty Trash in the Library stops listing when the server repeats a cursor or after 200 pages, like Empty Trash in a Space.
- Home suggestions are no longer generated each time ChatGPT goes to the background, and run at low reasoning effort instead of medium. The home view still refreshes them when you leave it, from its refresh button and after connecting a plugin.
- The composer's catch-up prediction is requested only while it can be shown, not while the composer holds attachments or queued messages or is dictating.
- Each turn carries the repository's git state (up to 3.9 KB) only when it changed since the thread last received it, and again after the history is compacted or rolled back, instead of on every turn.
- A streaming code block without a language reuses the language it detected instead of trying every grammar on each update (every 120 ms), detecting again as it grows and once more when it settles.
- The integrated terminal renders with WebGL instead of xterm's DOM renderer, which rebuilt a row of elements for every changed line and pinned the window during heavy output. Codex++ ships the matching renderer (`@xterm/addon-webgl` 0.18.0 for the bundled xterm 5.5) unmodified and loads it once per terminal; without WebGL, or if the GPU context is lost, the terminal goes back to the DOM renderer.
- A background command's output terminal no longer resets and rewrites itself on every update once its output passes the 16–20 KB cap; only the new lines are written, so it stops flickering and keeps its scroll position.
- Terminal output is sent from the main process to the window in batches of up to 8 ms instead of one message per pty chunk. The first output after a pause is still immediate, and output always arrives before the exit. The integrated terminal refits at most once per frame when several refits are requested together.
- Idle Pages: ChatGPT keeps a closed Page's realtime connection for 2 minutes, with no limit on how many, so browsing many pages left many sockets open. At most four idle Page connections are kept; older ones close, and pages with unsaved edits or drafts are never closed early.
- Expanded folders in the Space sidebar refreshed their child pages every 30 s even while a chat was showing; like the spaces list, they now poll only on Space routes.
- Empty Trash stops listing deleted pages on a repeated cursor or after 200 pages, instead of following the server's cursor without a limit.
- Changing a Space's icon or colour while a previous change was still saving lost the second change; it is now saved as soon as the first save succeeds.
- Warnings the app-server writes to stderr are no longer recorded as connection errors and broadcast to every window while the host stays connected (hundreds of times in two days in one Mac's logs); the last line is still reported if the process exits.
- The remote-control websocket backs off between reconnect attempts (1 s doubling to 30 s, with jitter) instead of re-enrolling and retrying every second.
- ChatGPT live updates reconnect sooner after an outage: the retry delay is capped at 60 s (it grew without limit), and focusing the window or the network coming back reconnects at once.
- After a websocket reconnect, the conversation on screen starts resuming at once instead of waiting for the full recent-threads refresh.
- The Remote Connections settings page no longer refreshes its connection lists every 15 s while the window is hidden.
- Re-registering a Browser sidebar window with the same owner no longer records a debug event and writes a log line on every browser-panel request (30,036 identical lines in two days in one Mac's logs, up to 138 a second).
- The startup probe no longer exits the moment Electron is ready. Chromium's utility processes were still starting then, and one would trap without its parent and leave a "Codex (Service)" crash report (8 in two days on one Mac). It now lets them finish starting and quits in order.

## 2.0.0 — 2026-10-14

Codex++ 2.0 is a new implementation for the ChatGPT desktop app (`com.openai.codex`): a signed macOS menu-bar helper that stages, probes and atomically installs a patched copy of the app, built and signed locally with your own Developer ID. It shares no code with Codex++ 1.x (the Node-based tweak system), whose source stays on the `legacy-1.x` branch and whose tags and releases are unchanged. 1.x tweaks are not loaded by 2.0; extensions use the contract in the README.

Upgrading from 1.x: quit ChatGPT, run `codexplusplus uninstall` (add `--purge` to also delete 1.x tweaks and data), then build and install 2.0. 2.0 only patches an app that still carries OpenAI's signature, so it refuses an app 1.x has modified. 1.x's background update check will see 2.0 as its latest release and fail before changing anything, because 2.0 is not a 1.x package.


- Initial source release of the Codex++ macOS menu bar helper and renderer extension host.
- Exact-build patch recipes, authenticated update handoff, atomic rollback, native Settings integration, Appshot compatibility, AutoFill, bookmarks, Better Sidebar, and Focus Mode.
- Main-process extension injection without an externally reachable DevTools endpoint.
- Extension polling sends code to a window only when it changes; steady-state polls are a small status probe. Polls no longer overlap, a hung window cannot queue calls, and diagnostics are rewritten only on change or every five seconds.
- Patch v41 (v37–v40 unreleased): an optional better-sidebar contract discovered by code shape replaces minified export names; the browser menu adapter tolerates an upstream `frame` option.
- Extensions can report non-fatal warnings with `api.warn`.
- Appshot runtime warmup waits 15 seconds after launch instead of starting while the first window loads, and its vendor signature checks no longer block the main process. A capture requested earlier starts the runtime itself. `scripts/bench-startup.py` compares cold-launch time to interactivity of the patched and original apps.
- The helper menu no longer pops open on every ChatGPT launch; the bootstrap's background `open -g` reopen is ignored unless it activates the helper.
- Startup fast path (optional AST adapter, `codexpp-startup-discovery.json` reports what matched): ChatGPT sign-ins build the Statsig client from the last bootstrap payload for the same identity (kept in IndexedDB) instead of holding the whole window behind a spinner until OpenAI's bootstrap request returns, then apply the fresh payload when it arrives; Statsig's cached values end its async loading state; the dictation sound cues are no longer preloaded at launch. A first launch, a different account or app version, or an unrecognised build behaves exactly as before.
- The Dock icon preference is applied 3 s after launch instead of before the first window exists (about 65 ms earlier window).
- Hidden prewarmed windows (new Page window, avatar overlay, hotkey window, detached window) are created when their feature is first opened instead of 3–13 s after launch: about half the CPU and 45% less memory 25 s after launch. `bench-startup.py --steady N` measures CPU and memory N seconds after launch and `--idle A:B` the idle CPU between two points, and traced launches list each window's route, TanStack query waterfall, running animations and console-error sources; `trace-report.py` reports jank in the 5 s after interactive.
- The loading shimmer ("Thinking", "Working for …") runs on the compositor: the label is drawn once and a highlight copy slides under a moving window, with the same path, timing and colours, instead of repainting the text on every step. A visible shimmer costs about half the CPU (26.8% → 13.2% of a core, median of three runs each). Labels with more than plain text keep the original shimmer. The `demoShimmer` experiment shows a fixed label for A/B tests. It pauses while the window is in the background.
- With the side panel open, the chat column no longer jitters while the window resizes. The shell measured its width with a ResizeObserver, which runs after layout, and the panel width it drives was written on the next frame, so the chat column took the whole change for one frame and snapped back. Observers of window-wide elements now get their new size from the window's resize event, before the frame is laid out. In a scripted resize the chat/panel divider jumped backwards 132 times (stock) and now does not move at all.
- Window resizing no longer restyles and relays out the whole window at every breakpoint. ChatGPT's main stylesheet has 47 width media queries, and each time the window crossed one Chromium rebuilt the sheet, reset every `@font-face`, `@property` and `@keyframes` rule and recomputed all of the window's styles, about 50 times in a 6 s resize of a long thread. Width-only media rules now run as container queries on `<html>`, which is always exactly the viewport, so a breakpoint only restyles what it styles. In that resize, style work fell from 971 to 409 ms, layout from 889 to 579 ms and main-thread busy time from 4.2 to 3.4 s; frames longer than 16.7 ms went from 62 (1.9 s in all) to 18 (0.5 s), and frames longer than 33 ms from 34 to 3.
- Resizing the window with the side-panel browser open no longer freezes it. The panel's browser reports its bounds on every frame, and each report rebuilt ChatGPT's whole application menu: 1.6 s of main-process work in a 12 s hand resize, ending in a 0.9 s garbage collection during which nothing was drawn. A burst of reports now rebuilds the menu once at the start and once 250 ms later. In the same hand resize the main process went from 3.5 s busy to 1.5 s, the longest garbage collection from 448 ms to 6 ms, the longest gap between frames from 872 ms to 68 ms (seven over 100 ms before, none after) and the frame rate from 85 to 113 per second.
- A turn no longer sets off repeated MCP inventory refetches. Each MCP server of a new thread (including the hidden thread that predicts the next prompt after every turn) reported ready separately, and each report refetched the host's MCP inventory, which starts every MCP server again; a short turn cost four extra inventory requests and about 24 node process launches. Ready reports now collapse into one trailing refetch per thread, skipped when the inventory was fetched in the last minute. `scripts/process-sampler.py` records CPU, spawned processes and memory of ChatGPT's whole process tree while it works.
- Personal accounts no longer boot a hidden, signed-in chatgpt.com checkout page at launch (about 250–350 MB); the upgrade and credit pages load when opened. `bench-startup.py --steady` also reports the true memory footprint (macOS `footprint`), and traces list every web contents and iframe with its process, query result sizes and the JS heap.
- A focused, untouched ChatGPT window no longer spends about 12% of a CPU core redrawing its blinking text cursor: the caret blinks for 5 s after activity, then stays steady (steady with Reduce Motion).
- Extension sync is event-driven: settings and extension file changes and window loads sync at once, and an idle app is checked every 4 s instead of every second (two scripts per window per second before).
- The helper menu shows how many startup speed-ups matched the installed ChatGPT build and lists any that did not, so a ChatGPT update that breaks one is visible.
- Benchmark experiments for development builds only (`CODEXPP_EXPERIMENTS=1 ./scripts/build-app.sh`), read from `Diagnostics/experiments.json`: scripted window resizes and side-panel toggles, Chromium traces of them or of a hand-driven session, script probes, injected stylesheets, renderer V8 flags, a forced opaque window surface and a fixed shimmer label. Release bootstraps contain none of this code and never read the file. The Node compile cache for the main-process bundles is always on.
- `scripts/evidence-video.py` films stock and patched ChatGPT under identical conditions (window resize, side-panel toggles, idle cursor, shimmer) with a live CPU readout of the whole process tree and renders labelled side-by-sides; `process-sampler.py --bundle` samples the untouched original bundle.
- Release tooling: `check.sh` runs the startup adapter and tracer tests, `check-release.sh` no longer needs ripgrep, and `release-source.sh` archives the repository root.
- Codex++ updates itself from GitHub releases: a daily check verifies an SSH-signed release manifest against the release key compiled into the helper, downloads and verifies the source tarball, builds and signs it locally with the pinned Developer ID in the background, and offers **Restart to Update**. The staged helper swaps itself in atomically and rolls back if it does not start; the menu then offers to repatch ChatGPT with the new revision. `release-source.sh` writes and signs the schema-2 manifest, and a release workflow publishes a drafted release only when its rebuilt tarball and signature match.
- Audit fixes: release builds carry no startup tracer, compile cache or diagnostic edits; code Codex++ loads lives inside the signed patched app; injected scripts no longer run with user activation; the cached shell environment keeps only allow-listed variables; the staged copy is re-authenticated before re-signing and the patched app must carry the pinned signer; the swap waits for ChatGPT's own processes to exit and stale transactions no longer block repatching; an unreadable settings file stops every extension.
- Opt-in startup tracing in development builds (`Diagnostics/trace.enable`): Codex++ spans, main-thread stalls, vendor IPC and module timings, renderer extension costs, loading-gate timings and a renderer CPU profile; `scripts/trace-report.py` ranks them and `scripts/startup-critical-path.py` rebuilds the request timeline from ChatGPT's own logs. Extensions now start concurrently, so a slow initializer no longer delays the others.
