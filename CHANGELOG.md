# Changelog

## 0.1.0 — unreleased

- Initial source release of the Codex++ macOS menu bar helper and renderer extension host.
- Exact-build patch recipes, authenticated update handoff, atomic rollback, native Settings integration, Appshot compatibility, AutoFill, bookmarks, Better Sidebar, and Focus Mode.
- Main-process extension injection without an externally reachable DevTools endpoint.
- Extension polling sends code to a window only when it changes; steady-state polls are a small status probe. Polls no longer overlap, a hung window cannot queue calls, and diagnostics are rewritten only on change or every five seconds.
- Patch v41 (v37–v40 unreleased): an optional better-sidebar contract discovered by code shape replaces minified export names; the browser menu adapter tolerates an upstream `frame` option.
- Extensions can report non-fatal warnings with `api.warn`.
- Appshot runtime warmup waits 15 seconds after launch instead of starting while the first window loads, and its vendor signature checks no longer block the main process. A capture requested earlier starts the runtime itself. `scripts/bench-startup.py` compares cold-launch time to interactivity of the patched and original apps.
- The helper menu no longer pops open on every ChatGPT launch; the bootstrap's background `open -g` reopen is ignored unless it activates the helper.
- Startup fast path (optional AST adapter, `codexpp-startup-discovery.json` reports what matched): ChatGPT sign-ins build the Statsig client from the last bootstrap payload for the same identity (kept in IndexedDB) instead of holding the whole window behind a spinner until OpenAI's bootstrap request returns, then apply the fresh payload when it arrives; Statsig's cached values end its async loading state; the dictation sound cues are no longer preloaded at launch. A first launch, a different account or app version, or an unrecognised build behaves exactly as before.
- The Dock icon preference is applied 3 s after launch instead of before the first window exists (about 65 ms earlier window). Startup experiments (`Diagnostics/experiments.json`) can pass renderer V8 flags (`jsFlags`), inject a stylesheet into app windows (`css`) or force ChatGPT's opaque window surface (`opaqueWindows`) for A/B tests.
- Hidden prewarmed windows (new Page window, avatar overlay, hotkey window, detached window) are created when their feature is first opened instead of 3–13 s after launch: about half the CPU and 45% less memory 25 s after launch. `bench-startup.py --steady N` measures CPU and memory N seconds after launch and `--idle A:B` the idle CPU between two points, and traced launches list each window's route, TanStack query waterfall, running animations and console-error sources; `trace-report.py` reports jank in the 5 s after interactive.
- The loading shimmer ("Thinking", "Working for …") runs on the compositor: the label is drawn once and a highlight copy slides under a moving window, with the same path, timing and colours, instead of repainting the text on every step. A visible shimmer costs about half the CPU (26.8% → 13.2% of a core, median of three runs each). Labels with more than plain text keep the original shimmer. The `demoShimmer` experiment shows a fixed label for A/B tests.
- A turn no longer sets off repeated MCP inventory refetches. Each MCP server of a new thread (including the hidden thread that predicts the next prompt after every turn) reported ready separately, and each report refetched the host's MCP inventory, which starts every MCP server again; a short turn cost four extra inventory requests and about 24 node process launches. Ready reports now collapse into one trailing refetch per thread, skipped when the inventory was fetched in the last minute. `scripts/process-sampler.py` records CPU, spawned processes and memory of ChatGPT's whole process tree while it works.
- Personal accounts no longer boot a hidden, signed-in chatgpt.com checkout page at launch (about 250–350 MB); the upgrade and credit pages load when opened. `bench-startup.py --steady` also reports the true memory footprint (macOS `footprint`), and traces list every web contents and iframe with its process, query result sizes and the JS heap.
- A focused, untouched ChatGPT window no longer spends about 12% of a CPU core redrawing its blinking text cursor: the caret blinks for 5 s after activity, then stays steady (steady with Reduce Motion).
- Extension sync is event-driven: settings and extension file changes and window loads sync at once, and an idle app is checked every 4 s instead of every second (two scripts per window per second before).
- The helper menu shows how many startup speed-ups matched the installed ChatGPT build and lists any that did not, so a ChatGPT update that breaks one is visible.
- Opt-in startup tracing (`Diagnostics/trace.enable`): Codex++ spans, main-thread stalls, vendor IPC and module timings, renderer extension costs, loading-gate timings and a renderer CPU profile; `scripts/trace-report.py` ranks them and `scripts/startup-critical-path.py` rebuilds the request timeline from ChatGPT's own logs. Extensions now start concurrently, so a slow initializer no longer delays the others.
